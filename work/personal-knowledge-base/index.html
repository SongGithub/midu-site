Personal project · 2026 · AI platform engineering

One knowledge base, available to the AI tools I use

I built a private, cloud-hosted MCP service so compatible AI clients can search my knowledge base and write new notes through a governed interface, without giving each assistant shell or SSH access to my home machine.

The problem

My notes were useful to the AI tools with local access, but isolated from assistants that could not reach my home setup. Copying knowledge between tools is cumbersome; granting broad machine access is a poor interface for a system that should expose only specific knowledge operations.

The goal was a durable service boundary: authenticate the person, authorize each operation in the backend, keep the Markdown source of truth private, and make the same MCP tools available to different AI clients.

Business value

  • Less repeated context setup: assistants can retrieve relevant notes from one shared source instead of relying on per-chat uploads or local machine access.
  • Knowledge can compound: an AI can propose and write a raw note through MCP; the normal ingestion pipeline can then chunk, embed and index it for later retrieval.
  • Narrower access: Google sign-in establishes identity; the MCP backend enforces authorization for search, fetch and write operations. The AI receives tool-level capabilities, not an SSH shell.
  • Portable interface: MCP separates the client's model and host from the knowledge service, making the same tools usable across compatible AI products.

Architecture

Markdown notes live in a private, encrypted S3 bucket. A separate private bucket stores the generated retrieval snapshot. An API Gateway HTTP endpoint fronts Lambda-based MCP and OAuth handling; the backend applies Google identity and service-side authorization. SQS and a worker support ingestion, while DynamoDB holds operational control state. Cohere Embed Multilingual v3 on Amazon Bedrock in Sydney generates document and query embeddings.

CloudFormation defines the AWS resources. A pinned CodeBuild release pipeline runs infrastructure lint, cloud service tests, the retrieval evaluation when the model or retrieval configuration changes, and then deploys the application. Cloudflare manages the custom DNS record; the API Gateway endpoint also remains available for unauthenticated smoke checks.

Evaluation is part of the release path

I expanded a fully synthetic benchmark to 20 notes and 33 judged queries, covering paraphrases, similar notes with different answers, exact identifiers and English/Chinese cross-language retrieval. It compares lexical, pure vector and hybrid strategies against the same query embeddings. No private note content is sent to this benchmark.

On the latest live Bedrock run, hybrid ranked the expected note first for 29 of 33 queries and in the top three for all 33. Pure vector reached 28/33 top one and 33/33 top three. Hybrid also reached 7/7 exact-identifier top one and 6/6 cross-language top three. These results pass the configured quality floor and default-winner gate. They are evidence on a synthetic fixture, not a claim of measured relevance on my private corpus; an owner-judged question set remains the next quality step.

The gate runs when the pinned model or retrieval configuration changes. This keeps model changes accountable without charging for a Bedrock benchmark on unrelated DNS-only changes.

An AI-native engineering workflow

I used MCP as the product interface and as an engineering boundary: tools have explicit contracts, identity is separate from authorization, and read/write behavior can be exercised without exposing a host machine. SpecKit artifacts record requirements, design decisions and implementation tasks. Tests cover the HTTP and Lambda adapters, storage and authorization boundaries, plus ranking behavior. The synthetic evaluation checks retrieval quality, while the deployment pipeline checks that infrastructure and application changes are reproducible.

AI-assisted implementation was useful for iterating across the spec, code, benchmark and infrastructure. The important control was a reviewable source commit and an automated quality gate before the release, not trusting generated code or a single successful demo.

Current status and limits

The cloud service and raw API Gateway URL are deployed. The health endpoint returns 200, and an unauthenticated MCP request receives the expected 401 Bearer challenge. The ACM certificate for mcp.midu.com.au is issued. Creating the API Gateway custom-domain mapping is pending an AWS account-level permission adjustment; the current deployment identity is explicitly blocked from that operation. ChatGPT OAuth also needs the exact callback URI from its custom-server setup added to the backend allowlist before authenticated use.

The current benchmark is synthetic and small. Retrieval abstention, broader private-corpus relevance and operational latency under regular use remain open areas. The service is a personal project, not a production offering for other users.
